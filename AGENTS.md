# Lever Workshop working agreement

- Keep the app a small, static browser game suitable for GitHub Pages and school Chromebooks.
- Use the existing VEX IQ CAD meshes and teacher build reference when changing the assembly. Check attachment geometry; visual resemblance is not physical verification.
- Keep ideal practice units distinct from real gear recipes. Never claim the 17 g and 22 g assemblies are 1 and 2 equal units.
- The real-world lab records observations. Adding computed physical outcomes requires calibrated mass, center-of-mass, shaft position, and friction assumptions with a real build check.
- No Newton calculations in this introductory release.
- Use finite positions and few weight levels. Every generated scored task must have a solution using its allowed controls.
- Require varied repeated demonstrations. A hint, incorrect prediction, repeated test, or corrected explanation is supported practice, not independent credit.
- Keep every student action on its own line or control. Prefer plain concrete language. Use Comic Sans first, with the bundled Comic Neue fallback. Use question numbers followed by `)`.
- Bold key terms; combine bold/underline/italic sparingly for critical directions.
- Never put private curriculum PDFs, rosters, or student identities in this public repository.
- Validate meaningful model and browser behavior. Report browser checks, physical checks, and instructional readiness separately.
- Do not deploy or merge without authorization. A development PR is the reviewable deliverable.
